# UI Development Rules

## 대시보드 수정은 /dashboard-implement 사용 필수
dashboard 코드(theme.py, components.py, pages/*.py, app.py) 수정 요청이 들어오면 **반드시 `/dashboard-implement` 스킬을 실행**한다.
직접 코드를 수정하지 않는다 — 스킬이 구현 → CSS 검증 → dashboard-review 체이닝을 자동으로 수행한다.
검증을 통과한 후에만 사용자에게 결과를 제시한다.

## 렌더링 검증 후 제시
UI/JS/HTML 변경은 실제 렌더링 결과를 검증한 후에만 사용자에게 확인을 요청한다.
- HTML/JS 변경 → 파일 저장 후 브라우저에서 확인 또는 문법 검증
- Streamlit 컴포넌트 → 가능하면 `streamlit run`으로 실행 확인
- 불가능하면 생성된 HTML 출력 + 로직 리뷰 후 제시
- validator 에이전트 활용: 코드 변경 결과물을 Black-box 검증

## P0 우선 검증
UI/CSS 수정 시 우선순위 기반 체크리스트를 따른다:
1. 사용자 요구를 P0/P1/P2로 분류한 뒤 작업 시작
2. 코드 수정 후 **P0부터 역순으로 검증** — P0가 깨지면 수정을 롤백
3. P0와 P1이 충돌하면 P1을 포기하거나 완전히 다른 접근법을 찾음
4. CSS 변경은 영향 범위를 먼저 파악 후 수정
5. 한 번에 하나의 요구사항만 수정하고, 이전 요구사항 유지 여부를 코드 레벨에서 확인

## 결정 체크리스트 워크플로우
사전 확인을 요청하지 말고, 최선의 판단으로 바로 구현한다.
단, 임의로 결정한 사항을 **체크리스트로 명시**하여 제시한다:
```
## 구현 완료 — 결정 사항 체크리스트
- [x] P0: 4개 박스 높이 동일 → height: 120px 고정
- [x] P1: YoY 뱃지 표시
  - 위치: 금액 아래 좌측
  - 폰트: 0.78rem
  - 색상: 상승=#10B981, 하락=#EF4444
```
사용자가 결과를 보고 체크리스트 항목 단위로 수정을 요청하면, 해당 항목만 변경하여 재구현한다.
